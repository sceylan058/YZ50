# WaveNet from Scratch (makemore Part 5)

A from-scratch reimplementation of `torch.nn` primitives (`Linear`, `BatchNorm1d`, `Tanh`,
`Embedding`, `Flatten`/`FlattenConsecutive`, `Sequential`), used to build a character-level
name generator with a WaveNet-style hierarchical architecture. Based on Andrej Karpathy's
["Building makemore Part 5: Building a WaveNet"](https://www.youtube.com/watch?v=t3YJ5hKiMQ0).

## Project structure

| File | Purpose |
|---|---|
| `layers.py` | From-scratch layer classes (`Linear`, `BatchNorm1d`, `Tanh`, `Embedding`, `FlattenConsecutive`, `Sequential`) |
| `model.py` | `build_model(...)` — assembles the layers into a `Sequential` model |
| `dataset.py` | Loads a word list, builds the vocabulary, and produces train/dev/test splits |
| `train.py` | Training loop; prints parameter count, loss curve, and final train/dev loss |
| `sample.py` | Loads a trained checkpoint and samples names from it |
| `wavenet.ipynb` | Notebook used for step-by-step shape debugging while building the model |

## Running an experiment

`train.py` and `sample.py` expose their configuration as plain constants at the top of the
file (`BLOCK_SIZE`, `N_EMBD`, `N_HIDDEN`, `DATA_PATH`), with the alternative values kept as
commented-out lines directly next to the active one. To run a different configuration,
comment out the active line and uncomment the one you want, then run:

```bash
python train.py
python sample.py
```

The architecture (flat vs. hierarchical) is chosen the same way in `model.py`. The
`BatchNorm1d` bug/fix toggle lives in `layers.py`, inside `BatchNorm1d.__call__`.

## Results

### 1. Context length, flat model

Same flat (single-`Flatten`) architecture, only the context window changes.

| Configuration | block_size | parameters | train loss | dev loss |
|---|---|---|---|---|
| Flat MLP | 3 | 17,997 | 2.0423 | 2.0955 |
| Flat MLP | 8 | 32,997 | 1.8678 | 2.0073 |

**Finding:** extending the context from 3 to 8 characters roughly doubles the parameter
count (the first layer's input size scales with `n_embd * block_size`) and lowers both
train and dev loss. More context helps, even without changing how it's merged.

### 2. BatchNorm 3D bug vs. fix

Hierarchical model, `block_size=8`, identical mini-batch order across both runs
(`torch.manual_seed(0)` fixed in `train.py`), so the only difference between the two runs
is the `BatchNorm1d` implementation.

| Configuration | parameters | train loss | dev loss |
|---|---|---|---|
| Buggy (`dim = 0` always) | 76,579 | 1.8060 | 1.9843 |
| Fixed (`dim = 0` for 2D, `dim = (0, 1)` for 3D) | 76,579 | 1.7650 | 1.9874 |

**Finding:** the bug computes batch statistics per-position instead of pooling across
batch and position, giving the model inconsistent normalization during training. This
shows up clearly in train loss (1.806 → 1.765). The effect on dev loss was small
(~0.003) at this model/data scale — the bug's main cost here was training-time signal
quality rather than generalization.

### 3. Scaled-up comparison

Same runs as above, collected into one table (flat context-3, flat context-8,
hierarchical WaveNet with the fixed BatchNorm).

| Configuration | context | parameters | dev loss |
|---|---|---|---|
| Flat MLP | 3 | 17,997 | 2.0955 |
| Flat MLP | 8 | 32,997 | 2.0073 |
| WaveNet (fixed BatchNorm) | 8 | 76,579 | 1.9874 |

**Finding:** for a fixed context length, restructuring how the 8 characters are merged
(flat concatenation vs. hierarchical pairwise fusion) further lowers dev loss, on top of
the gain from extending the context in experiment 1.
